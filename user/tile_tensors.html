Tile tensors#

Tile tensor is a powerful and simple tool for handling tensors under encryption. It takes care of the packing details, how a tensor is flattened, and how its data is laid out within ciphertexts, while offering the usual API of a tensor, with operations like add, multiply, sum-over-dim, etc.

The packing method is controlled by the tile tensor shape. This is a simple language that defines the shape of the tensor, and how it is packed.

The various options achievable with tile tensor shapes cover many packing options known in the literature (see examples below), unify them to a generic framework, generalize upon them, and add novel possibilities

To simplify working with tile tensors, they provide the same set of operators ordinarily supported by tensors: elementwise operators, matrix-multiplication, sum_over_dim, convolution, rotate (roll), slice, etc.

Here too, the way these operators are implemented covers and generalizes upon many known techniques from the literature. See examples below.

Other works offer frameworks to control different packing of tensors using various schemes.

  • Tile tensors offer the interleaved packing method, which allows

for rotating tensor dimensions with high efficiency and zero multiplication depth. While Fhelipe’s layouts can also be configured to schemes equivalent to interleaved packing, these configurations are less intuitive, and the rotation algorithms adapted to Fhelipe’s layouts require non-trivial multiplication depth.

  • Tile tensors keep better track of slots containing duplicate values

and unknown values. While both Fhelipe’s layout and tile tensors allow the user to request replication, tile tensors have the additional advantage of identifying cases where replication occurs spontaneously, e.g., after summation of a dimension under certain, simple conditions. If these conditions are not satisfied, then some slots will have unknown values, which are too tracked by the tile tensor metadata. Clearing them is not automatic as in Fhelipe, as they might not disrupt the rest of the computation, or be cleared as a side effect of one of the next operators.
